We evaluated NVIDIA SkillSpector as a potential addition to the openshift-eng/ai-helpers CI pipeline.

2. What Is SkillSpector?

Research basis42,447 skills surveyed from major marketplaces

SkillSpector answers one question: "Is this skill safe to install?"

It runs a two-stage analysis pipeline:

  1. Stage 1 (Static): Regex matching, Python AST analysis, taint tracking, YARA signatures, dependency CVE lookups via OSV.dev. Fast, no API keys needed.
  2. Stage 2 (LLM, optional): Sends file contents to an LLM to evaluate context and filter false positives. Claims ~87% precision with LLM vs ~50% without.

We tested Stage 1 only (--no-llm) and also tested a Claude-based triage as an alternative to Stage 2.

5. Noise Analysis & Examples

The core problem: SkillSpector assumes every skill it scans is an untrusted third-party artifact. Patterns that are suspicious from a stranger are business-as-usual in a first-party CI repo.

Credential Access (455 findings — all false positives)

The scanner flags any mention of credential-related strings. In an OpenShift skill repo, this means every reference to kubeconfig becomes a security finding.

6. Claude Triage Pipeline

We tested whether Claude could replace SkillSpector's built-in LLM mode to triage false positives. The pipeline is simple:

# Step 1: Run SkillSpector static analysis
skillspector scan ./path --no-llm --format json --output report.json

# Step 2: Have Claude triage the findings
claude --print --model claude-opus-4-6 \
  "Read report.json. First-party Claude Code plugin repo for OpenShift.
   Triage each finding as REAL, EXPECTED, or FALSE_POSITIVE. Be terse."
Results

We tested against two scopes:

ScopeReport SizeRaw FindingsClaude Verdict
Single plugin (plugins/jira/) 55 KB 37 0 REAL, 8 EXPECTED, 29 FALSE_POSITIVE
Full repo (all 45+ plugins) 1.3 MB 882 2 REAL (dep pinning), 857 EXPECTED, 23 FALSE_POSITIVE

Claude correctly identified every false positive and categorized expected behavior appropriately. The triage was thorough — e.g., it recognized that b374K in package-lock.json was an npm hash, not a webshell, and that "do NOT warn" was about suppressing irrelevant log noise, not safety bypasses.

Could this work in CI? Yes, technically. The two-command pipeline works. But when the answer is always "no real issues," paying $1.29/run to confirm that is waste.

8. Recommendation

Do Not Add SkillSpector to ai-helpers CI

Why not
  • Wrong threat model. SkillSpector is designed to evaluate untrusted third-party skills. ai-helpers is a first-party repo where the team writes all the skills.
  • Overwhelming noise. 882 findings, ~0 actionable. The suspicious-by-default posture flags normal CI behavior (kubeconfig, subprocess, curl) as threats.
  • Duplicates existing coverage. The only real findings (dependency pinning) are already caught by Dependabot. Quality issues are caught by skillsaw.
  • Cost with no return. Claude triage costs $0.71–$1.29/run to confirm "everything is fine."
Where it does add value
  • Evaluating third-party skills before installation. Run skillspector scan https://github.com/someone/skill --no-llm as a one-off before installing unknown skills. This is its intended use case.
  • Marketplace gating. If ai-helpers ever accepts submissions from untrusted external contributors at scale, SkillSpector could serve as a first-pass gate.
  • Security awareness. The 17 threat categories are a useful taxonomy for thinking about skill security, even if the scanner itself isn't the right CI tool.
