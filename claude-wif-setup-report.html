Claude Code WIF Auth

End-to-end setup of Claude Code with GCP Workload Identity Federation in GitHub Actions — keyless, short-lived credentials, no stored secrets.

The key insight: no stored secrets. GitHub mints a short-lived OIDC token for each workflow run, GCP validates it against attribute conditions, and issues temporary credentials scoped to Vertex AI only.

Why issue_comment?
  • Fork PRs can't get id-token: write — GitHub won't mint OIDC tokens for pull_request events from forks, so WIF auth is impossible with that trigger. In openshift/hypershift, all PRs come from personal forks.
  • issue_comment runs from main — the workflow always executes from the default branch, not the PR branch. A "Get PR ref" step fetches the PR's head branch via the GitHub API and checks out that code.
  • Chicken-and-egg — changes to the workflow file itself can't be tested until they're merged to main.

Step 4 was the final blocker. The WIF provider uses an organization allowlist. Each GitHub org that needs to authenticate must be explicitly added. Without openshift in the list, every auth attempt returned: "The given credential is rejected by the attribute condition."

ARC Runner Constraints

All GHA runners in openshift/hypershift are self-hosted via Actions Runner Controller (ARC) on Kubernetes. Key constraints that affect workflow design:

Runner Environment
ArchitectureARM (aarch64)
Runner labelarc-runner-set
Shellbash (but /bin/sh is dash)
HOMEUnset — must set HOME: /tmp
DockerNot available
gh CLINot pre-installed
What Didn't Work
  • container: directive — requires containerMode: kubernetes on ARC, which needs anyuid SCC for non-numeric UIDs. Even with SCC, the container exited immediately (no long-running entrypoint).
  • Pre-built container image — attempted but abandoned due to ARC compatibility issues.

Solution: install Claude Code and clone ai-helpers directly in workflow steps.
