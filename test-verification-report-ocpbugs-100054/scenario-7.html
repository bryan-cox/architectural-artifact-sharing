Scenario 7: Infra Destroy Handles Both DNS Zone Naming Formats

Objective: Verify hypershift destroy infra azure cleans up DNS zones with both the old {name}-azurecluster.{baseDomain} and new {name}.{baseDomain} naming formats.

Overall Scenario 7: TBD — Requires tearing down the test cluster.
StepCheckResultEvidence
1 Destroy the cluster infrastructure TBD —
2 New naming format zone ({name}.{baseDomain}) is deleted TBD —
3 Old naming format zone ({name}-azurecluster.{baseDomain}) is also deleted TBD —

Current State

The managed resource group brcox-100054-hc-brcox-100054 currently has both naming formats present (see Appendix G):

brcox-100054-hc-azurecluster.hcp-sm-azure.azure.devcluster.openshift.com   # old (CAPZ)
brcox-100054-hc.hcp-sm-azure.azure.devcluster.openshift.com               # new (hypershift CLI)

Implementation Detail

The hypershift destroy infra azure command was updated to attempt deletion of both naming formats. It first tries the new {name}.{baseDomain} format, then also tries the old {name}-azurecluster.{baseDomain} format. Both deletions are best-effort (404 is ignored), ensuring backward compatibility with clusters created before this fix.

Risk Assessment

Risk: Low — The destroy logic uses best-effort deletion for both formats. If one doesn't exist, the 404 is silently ignored. This is a purely additive change to the destroy path.
