Key Observations

  • Before this fix: Azure Private clusters without --external-dns-domain failed because KAS defaulted to LoadBalancer (not Route), CPO tried to create external routes without a hostname, and the private DNS zone naming used -azurecluster suffix.
  • After this fix: Cluster provisions to completion in ~8 minutes with correct Route strategy, correct DNS zone naming, and only internal KAS routes.
  • PublicZoneID kept: Aligned with AWS behavior — Private topology controls KAS visibility, not ingress DNS. The ingress operator successfully manages both public and private DNS zones.
