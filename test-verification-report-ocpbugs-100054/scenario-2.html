Scenario 2: KAS Route Defaulting for Private Clusters

Objective: Verify the CLI correctly defaults KAS to Route strategy for Private topology, matching the behavior when --external-dns-domain is set.

Overall Scenario 2: PASS — All 4 checks verified.

4 OAuthServer uses Route strategy PASS spec.services[3].servicePublishingStrategy.type = "Route". See Appendix E and raw evidence below.

Implementation Detail

The fix adds an isPrivate parameter to GetIngressServicePublishingStrategyMapping(). When isPrivate=true, the function returns Route strategy for APIServer instead of LoadBalancer, regardless of whether --external-dns-domain is set. This aligns with the expected behavior: Private clusters need Route-based KAS access through the management cluster's ingress, not a direct LoadBalancer.
