Scenario 6: SelfSubjectReview Claim Mappings (Azure AD)

Objective: Verify that the KAS JWT authenticator correctly maps Azure AD token claims to Kubernetes user attributes per the OIDC provider configuration.

Overall Scenario 6: PASS — All 3 checks verified.

Username preferred_username (prefixPolicy: NoPrefix) User's Azure AD UPN br...@redhat.com PASS
Groups groups (prefix: aad:) Azure AD security group IDs with aad: prefix 7 groups, all prefixed with aad: PASS
UID oid Azure AD object ID (GUID) aaa1f0e0-...f06f PASS

Claim mapping configuration (from HostedCluster OIDC config)

"claimMappings": {
    "username": {"claim": "preferred_username", "prefixPolicy": "NoPrefix"},
    "groups":   {"claim": "groups", "prefix": "aad:"},
    "uid":      {"claim": "oid"}
}
Key observations:
  • Username: The preferred_username claim maps directly to the user's Azure AD UPN (br...@redhat.com) with no prefix, matching the NoPrefix policy.
  • Groups: Azure AD returns security group object IDs (GUIDs) in the groups claim. The aad: prefix distinguishes OIDC-sourced groups from Kubernetes-native groups. 7 security groups were returned.
  • UID: The oid claim (Azure AD object ID) is a stable, unique identifier for the user across all Azure AD applications.
  • The ExternalOIDCWithUIDAndExtraClaimMappings=true feature gate enables the UID claim mapping (GA in this release).
